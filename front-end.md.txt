# Heimdinger TUI — Especificación de Implementación

> Terminal User Interface para la app de coaching de League of Legends.
> Stack: **Textual** (Python) + **Rich** (ya instalado) + **Plotext** (gráficos ASCII).

---

## 1. Stack tecnológico

| Librería | Versión mínima | Rol |
|---|---|---|
| `textual` | ≥ 0.60 | Framework TUI — widgets, layouts, CSS |
| `rich` | ≥ 13.0 | Ya en el proyecto. Tablas, colores, paneles |
| `plotext` | ≥ 5.2 | Gráficos ASCII (barras, líneas, scatter) en terminal |
| `python-dotenv` | ya instalado | Config |

```bash
# Añadir al pyproject.toml o requirements.txt
pip install textual plotext
```

```python
# ingest_screen.py
class IngestScreen(Screen):
    def compose(self):
        yield Input(placeholder="TR Terminator#1998", id="riotid")
        yield Input(value="5", id="count", type="integer")
        yield Select(options=[("europe","europe"),("americas","americas")], id="region")
        yield Button("▶ INGESTAR", variant="primary", id="ingest_btn")
        yield RichLog(id="log", highlight=True, markup=True)

    @on(Button.Pressed, "#ingest_btn")
    async def run_ingest(self):
        log = self.query_one("#log")
        # Correr ingest_player en worker thread para no bloquear la TUI
        await asyncio.to_thread(ingest_player, riotid=..., count=...)
```

> **Patrón clave:** usar `asyncio.to_thread()` o `self.run_worker()` de Textual para todas las llamadas a la API de Riot y a Ollama. La TUI nunca debe bloquearse.

```python
# chart_widget.py
import plotext as plt
from textual.widget import Widget

class PlotextChart(Widget):
    def __init__(self, x_data, y_data, title="", color="cyan"):
        super().__init__()
        self.x_data = x_data
        self.y_data = y_data
        self.title = title
        self.color = color

    def render(self):
        plt.clf()
        plt.plot(self.x_data, self.y_data, color=self.color)
        plt.title(self.title)
        plt.plotsize(self.size.width, self.size.height)
        return plt.build()  # devuelve string ASCII
```

```python
# coach_screen.py
class CoachScreen(Screen):
    async def send_to_llm(self, question: str):
        bubble = CoachBubble(streaming=True)
        self.query_one("#chat_log").mount(bubble)

        # Ollama tiene API de streaming — usar httpx async
        async with httpx.AsyncClient() as client:
            async with client.stream("POST", "http://localhost:11434/api/generate",
                json={"model": self.model, "prompt": self._build_prompt(question)}
            ) as response:
                async for chunk in response.aiter_text():
                    data = json.loads(chunk)
                    bubble.append_text(data.get("response", ""))
                    await asyncio.sleep(0)  # yield al event loop

        bubble.streaming = False
```

## 5. Gráficos disponibles (Plotext)

Todos se renderizan como strings ASCII dentro de widgets de Textual.

| Gráfico | Widget | Datos de la API | Cuándo mostrarlo |
|---|---|---|---|
| **KDA trend** | `PlotextChart(type="line")` | `challenges.kda` × partida | Pantalla jugador |
| **GPM por partida** | `PlotextChart(type="line")` | `challenges.goldPerMinute` | Pantalla jugador |
| **Win rate equipo** | `PlotextChart(type="bar")` | `win` agregado × jugador | Dashboard |
| **CS@10 vs benchmark** | `PlotextChart(type="bar")` | `laneMinionsFirst10Minutes` | Pantalla jugador (laners) |
| **Daño % del equipo** | `PlotextChart(type="bar")` | `challenges.teamDamagePercentage` | Pantalla jugador |
| **Vision score/min** | `PlotextChart(type="scatter")` | `challenges.visionScorePerMinute` | Support / Jungle |
| **Distribución muertes** | `PlotextChart(type="bar")` | `totalTimeSpentDead` | Pantalla jugador |
| **Kill Participation** | `PlotextChart(type="bar")` | `challenges.killParticipation` | Dashboard |

**Ejemplo de gráfico de barras múltiple (comparativa de equipo):**
```python
def render_team_kda_chart(players: list[dict]) -> str:
    plt.clf()
    names = [p["riotId"][:8] for p in players]
    kdas  = [p["kda"] for p in players]
    plt.bar(names, kdas, color="gold")
    plt.title("KDA promedio por jugador")
    plt.ylim(0, 10)
    plt.plotsize(60, 15)
    return plt.build()
```

## 8. Entrypoint

```python
# tui/app.py
from textual.app import App, ComposeResult
from textual.widgets import Header, Footer
from tui.screens.dashboard import DashboardScreen

class HeimdingertApp(App):
    CSS_PATH = "heimdinger.tcss"
    TITLE = "Heimdinger — LoL Coaching"
    BINDINGS = [
        ("q", "quit", "Salir"),
        ("f1", "help", "Ayuda"),
        ("f5", "refresh", "Refrescar"),
        ("1", "goto_dashboard", "Dashboard"),
        ("2", "goto_ingest", "Ingestar"),
        ("3", "goto_coach", "Coach"),
        ("4", "goto_pipeline", "Pipeline"),
    ]

    def on_mount(self):
        self.push_screen(DashboardScreen())

if __name__ == "__main__":
    HeimdingertApp().run()
```

Lanzar con:
```bash
python -m tui.app
# o
textual run tui/app.py
```

## 9. Integración con el código existente

El `main.py` actual sigue siendo válido como fallback CLI. La TUI llama a los mismos módulos internos:

| Función en `main.py` | Módulo reutilizado en TUI |
|---|---|
| `_run_ingest_one()` | `modules.ingest.lib.ingest_player` |
| `_run_ingest_team()` | `modules.config_manager.get_team` + `ingest_player` |
| `_run_coach_interactive()` | `scripts.ask_coach.ask_coach` (o llamada directa a Ollama) |
| `_run_pipeline()` | `ReportBuilder`, `LLMAdvisor`, `ingest_player` |

> Toda llamada bloqueante (Riot API, Ollama, DB) debe envolverse en `asyncio.to_thread()` o `self.run_worker()` para que la TUI no se congele.

## 10. Orden de implementación recomendado

1. **Setup** — instalar Textual + Plotext, crear estructura de carpetas `tui/`
2. **`app.py` + `heimdinger.tcss`** — esqueleto con sidebar y navegación
3. **`dashboard.py`** — DataTable del equipo + StatCards (sin gráficos aún)
4. **`ingest_screen.py`** — formulario + RichLog + worker async
5. **`chart_widget.py`** — wrapper Plotext genérico
6. **`player_screen.py`** — detalle con gráficos de línea/barra
7. **`coach_screen.py`** — chat con streaming de Ollama
8. **`pipeline_screen.py`** — progreso en tiempo real con workers
9. **Pulido** — colores, atajos de teclado, mensajes de error, modo ayuda
